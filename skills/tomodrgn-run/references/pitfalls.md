# tomoDRGN pitfalls and sizing (general)

Checked against tomoDRGN 1.0.5. Function/flag names, not source line numbers, because lines move between releases.

## Data going in
- **Premultiplication.** WarpTools exports premultiplied by default (`_rlnCtfDataAreCtfPremultiplied 1`); export with
  `--dont_premultiply` for tomoDRGN. tomoDRGN reads the flag, but training on non-premultiplied series is the tested
  path, and `tomodrgn backproject_voxel` of premultiplied images looks hollow by design. Judge polarity and quality
  on volumes generated by the trained model (`analyze` / `eval_vol`), not on backprojections.
- **Negative coordinates** -> train_vae refuses the STAR. Drop or clamp upstream, re-export.
- **Stale per-particle optics columns.** `ts_export_particles` passes unknown input columns through. tomoDRGN merges
  optics into particles keeping the PARTICLE copy, so an old `_rlnImageSize` or pixel size gives a wrong-sized CTF
  with no error. `prep_tomodrgn_star.py` strips them.
- **Origins.** A refined STAR carries `_rlnOrigin*Angst`; fold them into the centres before re-exporting, or the
  particles are re-extracted off-centre by the refinement shifts (tens of A is common).
- **Coordinate units.** Export STARs: export pixels (`_rlnImagePixelSize`). Warp per-series input STARs: the
  `--coords_angpix` units. Mixing them is the usual cause of a failed join.
- **Cs.** All optics groups should carry the nominal Cs. After M refines Cs per group, exports inherit it; reset the
  metadata (`scripts/_lib/reset_ctf_cs.py`) and re-export.
- **Pose quality first.** With many wrong poses (e.g. a coarse global search), the latent space mostly encodes pose
  error. Improve poses before using tomoDRGN for biology; for cleaning, that error is what you want to find.

## Training
- **Polarity.** Default: data sign inverted. `--uninvert-data` disables it. Measure with prep's centre-vs-ring test
  and confirm on a trained model with `review_classes.py --polarity` (negative CC = wrong sign). A 1-epoch smoke
  model is usually too weak (|CC| < 0.2, "UNCLEAR").
- **Learning rate** is for batch 1, scaled by sqrt(batch). With `--multigpu` the batch is global.
- **Epoch choice.** The loss curve is not a convergence test; use `tomodrgn convergence_vae`. Analyse the epoch you
  will select from (default: the last).
- **Memory.** In RAM (no `--lazy`): ~ particles x tilts x box^2 x 4 bytes, plus overhead; request ~1.5x as `--mem`.
  `--lazy` reads from disk each epoch (slower, little RAM). GPU memory grows with batch, box and model width.
- **AMP warnings** appear unless batch and box are divisible by 8; harmless.
- **"fewer tilts than ..."** errors -> some particles have too few tilts; prep checks every particle against
  `--min-tilts`. `--use-first-ntilts N` drops particles with fewer than N tilts.
- **OUTDIR reuse.** Never train into an OUTDIR that holds a run (the script refuses); `LOAD=weights.N.pkl` continues.

## Choosing classes
- Run analyze at k = 50 and 100 (more than tomoDRGN's default 20) so small junk populations get their own classes.
- A 20 A low-pass CC cannot flag featureless blob classes (a blurred envelope still scores high). Band-pass (10-30 A)
  CC plus a detail score can; on other sets the low-pass CC separates junk better, hence the combined rank.
- Look at the volumes and the per-class particle images before deciding; the user makes the call.
- Validate a selection against a size-matched random subset refined with identical poses, mask and protocol.
- tomoDRGN cleaning and confidence-based culling (`_rlnMaxValueProbDistribution`) remove different particles and
  combine well: tomoDRGN removes structural outliers that still align confidently.

## Joining results
- `labels.pkl` has one entry per particle of the STAR train_vae actually used (`<OUTDIR>/*_tomodrgn_preprocessed.star`),
  in its order.
- Join to other STARs on (tomogram, centre in A) with a per-tomogram KD-tree. A join on `_rlnTomoParticleName` is
  wrong (renumbered every export) yet looks plausible, because every tilt series still gets matches.
- Check one-to-one: several kept particles hitting one target means duplicates or a loose tolerance, and inflates
  coverage. `select_and_map.py` fails on it by default.
- Permutation nulls for latent-vs-quality questions must shuffle within tomograms; global shuffles mistake
  tilt-series structure for a discovery.
